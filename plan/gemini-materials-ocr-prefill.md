# Project Inventory Import Plan

## Summary

Build one customer-facing import feature with two separate extraction paths:

- CSV import for structured project inventory templates.
- Gemini OCR import for PDFs, images, quotes, invoices, receipts, and takeoff documents.
- Both paths normalize into the same draft contract.
- The same review table is used before anything is saved.

This solves the customer problem of manually adding tools and materials one by one without tying the save workflow to one file format or one AI provider.

## Architecture

Keep extraction separate from review and save:

```text
CSV file
  -> CSV parser
  -> ProjectInventoryImportDraft
  -> Review table
  -> Save action

PDF/image
  -> Gemini OCR/extraction
  -> ProjectInventoryImportDraft
  -> Review table
  -> Save action
```

Shared draft shape:

```ts
type ProjectInventoryImportDraft = {
  projectName: string | null;
  tools: {
    name: string;
    status?: string;
    condition?: string;
    notes?: string;
  }[];
  materials: {
    name: string;
    quantity: number | null;
    unitCost: number | null;
    notes?: string;
  }[];
};
```

## CSV Import

The CSV should not mirror raw database tables. It should use construction-friendly columns:

```csv
project_name,item_type,name,quantity,unit_cost,condition,status,notes
Kitchen Remodel,tool,Cordless drill,,,Good,Available,Stored in trailer
Kitchen Remodel,tool,Laser level,,,Fair,Available,
Kitchen Remodel,material,2x4 lumber,120,4.25,,,
Kitchen Remodel,material,Drywall sheets,40,13.50,,,
```

Internal fields stay owned by the app:

- `org_id` comes from the authenticated account.
- `project_id` is resolved from `project_name` or confirmed by the user.
- Tool `tag_number` remains generated by the database trigger.
- `created_at` remains a database default.
- Images and storage paths are skipped in v1.

## Gemini OCR Import

Use Gemini as the first OCR provider for unstructured construction documents:

- PDF quote.
- Supplier invoice.
- Receipt photo.
- Delivery ticket.
- Material takeoff.
- Project setup document.

The Gemini path should:

- Accept PDF and image uploads.
- Send the file to a server action, never directly from the browser.
- Use a strict JSON schema matching `ProjectInventoryImportDraft`.
- Ask Gemini to return `null` instead of guessing uncertain quantities or costs.
- Keep provider logic isolated so OpenAI, Tesseract, Docling, or PaddleOCR can be swapped later.
- Never create tools or materials directly from OCR output.

## Current UI Scope

- Create `components/import/project-inventory-import-dialog.tsx`.
- Add the import trigger beside `Add Tool` on `/tools`.
- Add the import trigger beside `Add Material` on `/materials`.
- Show two import method panels:
  - CSV template upload, parsed into the preview table now.
  - Gemini OCR upload, visible as the planned PDF/image path but not connected yet.
- Keep the final import action disabled until backend save work is added.

## Future Backend Changes

- Create `app/services/project-inventory-import-services.ts` for shared save.
- Create `app/services/project-inventory-ocr-services.ts` for Gemini extraction.
- Add `GEMINI_API_KEY=` to `.env.example` when implementing OCR.
- Require authenticated org membership with `requireOrgMember()`.
- Verify that the caller can manage tools/materials.
- Resolve `project_name` to an existing organization project or require explicit user confirmation.
- Insert tools and materials in one service workflow.
- Revalidate `/tools`, `/materials`, and the affected project detail route.
- Keep bulk business logic in `app/services/*`; keep reads/mapping in `lib/dal/*`.

## Future File Expansion

- Add `.xlsx` import after CSV if customers already maintain equipment/material spreadsheets.
- Skip `.ods` unless a real customer specifically uses LibreOffice/OpenDocument files.
- Consider OpenAI only if Gemini extraction quality is not good enough for construction documents.

## Test Plan

- Validate CSV UI behavior:
  - No file selected.
  - Unsupported file type.
  - Missing required headers.
  - Empty CSV.
  - Tool rows.
  - Material rows.
  - Mixed tool and material rows.
  - Unknown `item_type`.
- Validate Gemini OCR placeholder UI:
  - PDF selected.
  - Image selected.
  - Unsupported file rejected.
  - OCR path clearly says extraction is not connected yet.
- Verify preview behavior:
  - Project name is detected from CSV.
  - Existing project names are recognized.
  - Row counts match parsed rows.
  - Invalid rows show friendly feedback.
  - Closing the dialog clears local file and preview state.
- Run `npm run type-check`.
- Run `npm run lint`.

## Assumptions

- Current implementation is UI only.
- CSV preview is implemented first because it is reliable and free to run.
- Gemini OCR is shown as the next import method but should not call Gemini until the backend service is implemented.
- No database changes in the UI-only pass.
- No scan history, source file persistence, or Supabase storage in v1.
